# Bug Investigation: v2 loop missing invocation metadata display

## Symptom
When running `gromit run2`, the terminal output no longer shows which provider, model, reasoning level, or prompt size is being used for each LLM invocation. The legacy runner displayed this via `BuildStartEvent` ("Building (sonnet, attempt 1/2)...") and `ModelSelectedEvent` ("Model: sonnet (priority-based)"), but the v2 loop shows only generic stage start/complete log lines with no invocation metadata.

Additionally, `bead_complete` events in the JSONL logs show `"Model":"","CostUSD":0,"InputTokens":0,"OutputTokens":0` — the v2 bead loop never populates these fields from build artifacts.

## Root Cause
The v2 loop code path omits invocation metadata events entirely:

1. **No typed event for build invocation metadata**: `internal/v2/event/event.go` defines `StageStartedEvent` but no `BuildInvocationEvent` that carries model, provider, tier, prompt size, or reasoning level.

2. **Build stage doesn't emit events**: `internal/v2/stage/build/build.go` has an `events.EmitterMixin` but never calls `Emit()`. The `Run()` method selects a model (line 259), invokes with escalation (line 266), and returns `BuildArtifacts` with model/tokens/cost — but never emits any of this to the event stream.

3. **Bead loop doesn't propagate artifacts to bead_complete**: `internal/v2/loop/bead_loop.go` emits `BeadCompletedEvent` (line 706) but never reads `BuildArtifacts` from the stage result. The `BeadCompletedEvent` struct itself lacks model/cost/token fields.

4. **Event bridge has no build invocation mapping**: `internal/v2/event/bridge.go` has no case for converting a build invocation typed event to legacy `BuildStartEvent`/`BuildCompleteEvent`/`ModelSelectedEvent`.

5. **Router selection is invisible**: The bead loop's `runStageEntry()` (lines 442-460) selects provider/model via the router, but this selection is never logged or emitted — it's only passed into the stage request.

## Affected Code
- `internal/v2/event/event.go` — missing typed event types for build invocation
- `internal/v2/stage/build/build.go:230-282` — `Run()` never emits events
- `internal/v2/loop/bead_loop.go:439-460` — router selection not logged
- `internal/v2/loop/bead_loop.go:702-718` — `emitBeadCompleted` missing artifact fields
- `internal/v2/event/bridge.go` — no bridge for build invocation events
- `internal/events/cli/subscriber.go:113-114,146-147` — handlers exist but never triggered

## Suggested Fix
Add build invocation typed events, emit them from the build stage and bead loop, bridge them to legacy events, and populate bead_complete with build artifact data. See plan at `.gromit/plans/fix-v2-invocation-metadata-events.md`.

## Evidence
- JSONL logs show all `bead_complete` events with empty Model and zero cost/tokens:
  ```json
  {"type":"bead_complete","payload":{"Model":"","CostUSD":0,"InputTokens":0,"OutputTokens":0}}
  ```
- Stage log lines show only generic messages:
  ```
  [info] stage build:default started for bead gromit-htng6 (iteration 2)
  [info] stage build:default completed for bead gromit-htng6 (iteration 2, duration 2m43.325236084s)
  ```
- Legacy CLI subscriber has working handlers for `BuildStartEvent` and `ModelSelectedEvent` that produce the expected output format — these handlers are simply never invoked by the v2 code path.
- The v2 build stage returns `BuildArtifacts` with all the needed data (Model, Tokens, CostUSD, Duration) but this data is never surfaced to events.

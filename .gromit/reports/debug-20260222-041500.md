# Bug Investigation: Orchestrator pipeline missing observability

## Symptom
Even after the spec-label-filtering and observability fix (84ccd499), a running gromit process produces very little visible output. The build phase appears to hang silently for minutes with no streaming output, heartbeats, or tool call progress.

## Root Cause
`invokerAdapter.StreamRun()` in `internal/runner/constructor.go:88` called `p.Run()` (blocking, non-streaming) instead of `p.StreamRun()`, silently discarding the output writer, event handler, and tool call handler parameters. This meant the entire LLM build phase produced zero live output.

## Fix Applied
Changed `p.Run(ctx, prompt, tier)` to `p.StreamRun(ctx, prompt, tier, w, handler, onToolCall)` in the `invokerAdapter.StreamRun()` method. 1-line fix; all tests pass.

## Remaining Observability Gaps

These secondary issues were identified during investigation and remain open:

### 1. statusWriterAdapter passes empty/zero values
**File:** `internal/runner/constructor.go:211-216`
**Issue:** The adapter calls `sw.Write(iteration, beadID, beadTitle, "", true, 0, 0)` — model is always empty string, maxIterations and timeBudgetMinutes are always 0. The resulting `status.json` has blank/zero values for these fields, making it much less useful for monitoring.
**Fix:** Plumb model name, maxIterations, and timeBudgetMinutes through `pipeline.Input` and the `epilogue.StatusWriter` interface so the adapter can pass real values.

### 2. Status only written after iteration completes
**File:** `internal/pipeline/epilogue/epilogue.go:188-192`
**Issue:** Status is written in Epilogue step 4, which runs after build+validate+review. There is no status update at the START of an iteration. The old Runner had a `statusHeartbeat` (`internal/runner/status_heartbeat.go`) that wrote status every 5 seconds during the build phase, keeping the status file current.
**Fix:** Either add a status write in the Orchestrator before calling the pipeline stages, or introduce a pre-iteration hook. The old `statusHeartbeat` pattern (goroutine with 5-second ticker) could be adapted for the Orchestrator.

### 3. Iteration JSONL logging not wired
**File:** `internal/runner/constructor.go:330-334`
**Issue:** `Epilogue.WithIterationLogWriter()` is never called in `newRunnerImpl()`. The `logWriter` field in Epilogue is nil, so no per-iteration JSONL entries are written to `~/.gromit/logs/run-*.jsonl`. Additionally, `pipeline.Input.Result` is never populated by the Orchestrator, so even if a writer were wired, there would be nothing to write.
**Fix:** Create an `IterationLogWriter` adapter, populate `pipeline.Input.Result` with an `IterationLog` entry in the Orchestrator after each stage, and wire it via `WithIterationLogWriter()`.

### 4. `gromit status` command broken
**File:** `cmd/gromit/main.go:231`
**Issue:** The status command explicitly returns `"status command is not yet available with the new orchestrator"`. It creates a runner but immediately errors out.
**Fix:** Implement a status display that reads `~/.gromit/status.json` (via `runner.ReadStatus()`) and formats it for the terminal. This is independent of the Runner/Orchestrator — it just reads the file.

### 5. getRunIDFn returns empty string
**File:** `internal/runner/constructor.go:356-359`
**Issue:** The function always returns `""`, which causes `Orchestrator.mergeGlobalStats()` to skip the merge entirely (line 212: `if runID == "" { return }`). Global stats are never updated.
**Fix:** Generate a run ID (e.g., from the stream logger path or a timestamp) and return it from `getRunIDFn`.

## Evidence
- `invokerAdapter.StreamRun()` at constructor.go:80-89 received streaming params but called `p.Run()` ignoring them
- The `execute.Build` stage (execute/build.go:113) correctly calls `b.invoker.StreamRun()` expecting live output
- The old Runner used `execution.Invoker.Execute()` (execution/invoker.go:65) which properly calls `p.StreamRun()` with heartbeat and event handling
- `statusWriterAdapter.Write()` at constructor.go:211-216 hardcodes empty/zero values
- `Epilogue.WithIterationLogWriter()` is defined (epilogue.go:130) but never called in the constructor
- `gromit status` at main.go:231 returns a hardcoded error message

# Bug Investigation: Review Findings Not Materialized as Beads on Main

## Symptom
A recent review appeared to create multiple beads, but those beads were not visible/synced on `main`.

## Root Cause
The reviewed changes were committed as backlog ideas (`idea-*`) in `.gromit/backlog.jsonl`, not as bd issues in `.beads/issues.jsonl`.

This is consistent with the current command flow:
- `gromit review` defaults to **interactive mode**.
- Interactive mode launches an agent session and returns without structured post-processing.
- Only non-interactive mode parses review JSON and creates tracked work items via pipeline adapters.

So there was no merge/sync loss of beads in this case; the expected beads were never created as bd issues.

## Affected Code
- `cmd/gromit/review.go:174` (interactive mode is default)
- `cmd/gromit/review.go:176` (interactive path)
- `internal/pipeline/pipeline.go:244` (`ReviewInteractive` launches agent with no post-processing)
- `internal/pipeline/pipeline.go:294` (`ReviewNonInteractive` handles structured parse + creation)
- `.gromit/backlog.jsonl:182` through `.gromit/backlog.jsonl:194` (review findings stored as `idea-*` entries)

## Suggested Fix
Add an explicit, deterministic bridge for interactive review sessions so findings are persisted to bd issues (or an equivalent tracker path), not only backlog ideas.

Recommended direction:
1. Add interactive review result ingestion (JSON parse + apply) after session completion.
2. Enforce/validate artifact type mapping (`beads_to_create` => bd issues; `backlog_items` => explicitly tagged backlog entries or separate sink).
3. Add guardrails in completion output to report exact artifact counts by sink and IDs created.

## Evidence
- `git show --name-status cdbaaa97` shows only:
  - `.gromit/LEARNINGS.md`
  - `.gromit/backlog.jsonl`
- No `.beads/issues.jsonl` change in the review commit.
- `.gromit/backlog.jsonl` contains 13 entries for context `from-review review-1772366501939692738`.
- Comparison of those 13 texts against `bd list --json` titles found 13/13 absent as bd issue titles.
- `git status -sb` shows `main...origin/main` (no evidence of unsynced local commit divergence causing loss).

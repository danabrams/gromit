# Bug Investigation: Spec branch checkout cascade failure on dirty worktree

## Symptom
Runs repeatedly fail beads with checkout errors like:

- `fatal: a branch named 'gromit/spec-remove-tdd-fresh-context' already exists`
- `error: Your local changes to the following files would be overwritten by checkout`
- `Please commit your changes or stash them before you switch branches. Aborting`

Observed behavior: each bead targeting the same spec branch is marked failed in sequence, creating a cascade of false bead failures caused by repository state, not bead logic.

## Root Cause
`CreateOrCheckoutSpecBranch` in `internal/runner/specbranch/git_ops.go` attempts:
1. `git checkout -b <branch>`
2. then fallback `git checkout <branch>`

When the branch already exists and the current worktree has uncommitted changes that conflict with target branch checkout, step 2 fails with Git's overwrite-protection error.

The checkout path has no pre-checkout repository-state validation (clean/dirty check + branch-state awareness), so this environmental precondition failure is discovered late and surfaced as a per-bead checkout failure.

In `internal/runner/orchestrator.go`, checkout failure in prelaunch is treated as bead-level failure (`marking bead ... as failed`) and the run continues, so the same precondition issue can fail many beads in a row.

## Affected Code
- `internal/runner/specbranch/git_ops.go:80` (`CreateOrCheckoutSpecBranch` checkout strategy)
- `internal/runner/specbranch/git_ops.go:93` (fallback checkout without precondition guard)
- `internal/runner/orchestrator.go:593` (checkout invocation)
- `internal/runner/orchestrator.go:594` (logs and classifies as bead failure)
- `internal/runner/orchestrator.go:617` (continues loop, enabling cascade)

## Suggested Fix
1. Add deterministic pre-checkout state validation in `specbranch`:
- Detect dirty worktree before branch switch attempts.
- Return a typed, actionable error for branch-switch-blocked state (include concise status details).

2. Handle this typed error in orchestrator as run-level prelaunch/environment failure behavior rather than repeated bead failures:
- Stop or short-circuit further bead attempts when checkout preconditions are unsatisfied.
- Emit one clear actionable message (commit/stash or use session worktree mode).

3. Add regression tests:
- `specbranch` test covering dirty-worktree pre-checkout detection.
- orchestrator test verifying non-cascading behavior for deterministic checkout precondition failures.

## Evidence
- Checkout logic is two-step create/fallback with no pre-checkout cleanliness guard:
  - `internal/runner/specbranch/git_ops.go:86`
  - `internal/runner/specbranch/git_ops.go:93`
- Orchestrator currently treats checkout errors as bead failures and continues iterating:
  - `internal/runner/orchestrator.go:594`
  - `internal/runner/orchestrator.go:617`
- Project learning explicitly calls for this missing behavior:
  - `.gromit/LEARNINGS.md:32` mentions deterministic branch checkout with pre-checkout state validation.

# Bug Investigation: v2 loop missing wallclock duration and cost for beads

## Symptom
In the current `gromit run2` execution, all `bead_complete` events in the JSONL log show `CostUSD: 0` despite beads completing successfully with real LLM invocations. The `IterationCompleteEvent` also shows `Duration: 0` for wallclock time. v1 captures both correctly.

## Root Cause

Four distinct bugs contribute:

### Bug 1: InputTokens uses wrong field (bead_loop.go:763)
`emitBeadCompleted` assigns `b.lastBuildArtifacts.Tokens` (total input+output) to `evt.InputTokens` instead of `b.lastBuildArtifacts.InputTokens`. Same bug at line 504.

### Bug 2: Bridge hardcodes Duration: 0 in IterationCompleteEvent (bridge.go:197)
`convertBeadCompleted` creates `IterationCompleteEvent{Duration: 0}` instead of propagating `e.Duration` from the typed event. The `BeadCompleteEvent` does propagate duration correctly, but downstream consumers reading `iteration_complete` events see zero.

### Bug 3: Validate/Review stage LLM costs not captured
v1 separately tracks `MidReviewCostUSD`, `FixBuildCostUSD`, etc. in `IterationLog` via `stampBuildAttribution()`. In v2, only `BuildArtifacts` carries cost/token data. When the validate stage triggers an LLM-based fix or the review stage invokes an LLM, those costs are silently dropped — they never appear in `BeadCompletedEvent`.

### Bug 4: Non-Claude provider cost may be zero
The event log shows models like `gpt-5.1-codex-mini` and `gpt-5.3-codex`. Cost extraction in `claude.go:processStreamJSONWithCost()` parses Claude CLI `result` events for `total_cost_usd`. If the Codex provider adapter doesn't emit cost in the same stream format, `CostUSD` will be zero even though the LLM was successfully invoked.

## Affected Code

- `internal/v2/loop/bead_loop.go:763` — wrong token field assignment
- `internal/v2/loop/bead_loop.go:504` — same wrong token field in BuildInvocationComplete
- `internal/v2/event/bridge.go:197` — hardcoded `Duration: 0`
- `internal/v2/loop/bead_loop.go:496-510` — only build stage metrics captured
- `internal/v2/stage/validate/validate.go` — no cost/token fields in ValidateArtifacts
- `internal/v2/stage/review/review.go` — no cost/token fields in ReviewArtifacts

## Suggested Fix

See spec at `.gromit/plans/fix-v2-cost-and-duration-capture.md`.

## Evidence

Event log entries showing $0 cost for completed beads:
```json
{"type":"bead_complete","payload":{"BeadID":"gromit-jp293","Duration":244790896917,"Model":"gpt-5.1-codex-mini","CostUSD":0,"InputTokens":2737614,"OutputTokens":18828}}
{"type":"bead_complete","payload":{"BeadID":"gromit-mqrdi","Duration":467965518625,"Model":"gpt-5.3-codex","CostUSD":0,"InputTokens":3933714,"OutputTokens":14999}}
```

Note: `Duration` and token counts ARE populated in `bead_complete` — the cost is the main zero field. The `InputTokens` values look suspiciously large (2.7M, 3.9M) which confirms Bug 1: these are total tokens (input+output), not just input.

v1 comparison: `stampBuildAttribution()` in `orchestrator_build_helpers.go:11-29` correctly maps `buildOut.CostUSD`, `buildOut.InputTokens`, `buildOut.OutputTokens` separately, and is called after every LLM invocation (build, mid-review, fix-build).

# Bug Investigation: TDD fresh-context cycles only run one cycle per execution

## Symptom
Beads processed by the TDD fresh-context orchestrator produce only 1-2 RED-GREEN cycles instead of many incremental cycles. Bead gromit-cr50o ("Restore formatting functions to format.go") required ~13 functions but was closed after implementing only 2 (formatRun, formatDuration).

## Root Cause
Three compounding problems:

### 1. Decompose prompt doesn't ask for `expected_outputs`
The decompose prompt template (`internal/pipeline/decompose.go:210-228`) listed required fields as "title, description, priority, acceptance_criteria, depends_on_index" — never mentioning `expected_outputs`. The `beadDef` struct supports the field and the code prefers it when non-empty (lines 171-174), but the LLM was never instructed to produce it.

### 2. Layer 2 description parser can't handle inline prose
`extractRequirementsFromDescription` handles comma-separated lists and headers at line start, but not inline headers embedded in prose like "...architecture migration. Functions: formatRun, formatRunningLine...". The `extractInlineHeader` function requires the header word to be at position 0 of the line.

### 3. Layer 3 LLM prompt was underspecified (already fixed)
The haiku prompt previously said "Extract the requirements... Return each requirement on its own line" without granularity guidance. Already fixed on main with "Extract the individual deliverables... Do not summarize. Do not group items."

## Affected Code
- `internal/pipeline/decompose.go:210-228` — decompose prompt template (FIXED)
- `internal/runner/process_methodology.go:75-91` — `extractInlineHeader` only matches line-start headers
- `internal/runner/process_methodology.go:118-185` — `extractRequirementsFromDescription` comma parsing (already on main)
- `internal/runner/process_methodology.go:15-47` — `extractRequirementsViaLLM` improved prompt (already on main)

## Fix Applied
Updated the decompose prompt template to include `expected_outputs` in required fields and instruct the LLM to populate it with fine-grained, individually testable deliverables. Added test `TestDecomposePrompt_MentionsExpectedOutputs`. All 46 packages pass.

Additionally, backfilled `acceptance_criteria` (which maps to `ExpectedOutputs`) on 32 open beads that were missing them, including gromit-cr50o with 12 individual criteria.

## Evidence
- Bead gromit-cr50o JSON: `expected_outputs` absent, `acceptance_criteria` absent before fix
- Git log: only 2 red/green commit pairs (formatDuration, formatRun) vs 13 required functions
- decompose prompt template missing `expected_outputs` field instruction
- `bead.resolveExpectedOutputsFromAcceptanceCriteria()` converts acceptance_criteria lines to ExpectedOutputs automatically

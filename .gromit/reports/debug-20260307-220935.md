# Bug Investigation: codex provider receives Claude-specific CLI flags

## Symptom
Running `gromit run2` with multi-provider routing fails when triage stage routes to the openai/codex provider:
```
running spec immutable-pipeline: triage: stage triage:default: triage: invoking llm: parse claude json: no json output from claude (raw: "STDERR:\nerror: a value is required for '--profile <CONFIG_PROFILE>' but none was supplied\n\nFor more information, try '--help'.")
```

## Root Cause
`claudeAdapter.Invoke()` in `internal/v2/adapter/llm/claude.go:43` hardcodes Claude-specific CLI flags:
```go
args := []string{"-p", "--model", req.Model, "--output-format", "json"}
```

All providers (including codex/openai) are created via `NewClaudeAdapter` in `cmd/gromit/run2.go:310`:
```go
providers[name] = llm.NewClaudeAdapter(provBinary, provFlags, timeout)
```

This ignores the `prompt_delivery` and `prompt_flag` config fields entirely. When routing sends a request to the codex binary:
- `-p` means `--profile <CONFIG_PROFILE>` in codex (requires a value), not `--print` as in Claude CLI
- `--output-format json` doesn't exist in codex (codex uses `--json`)
- codex requires `exec` subcommand for non-interactive mode

## Affected Code
- `internal/v2/adapter/llm/claude.go:43` — hardcoded `-p` flag in `Invoke()`
- `internal/v2/adapter/llm/claude.go:75-91` — hardcoded Claude flags in `StreamInvoke()`
- `cmd/gromit/run2.go:310` — all providers created via `NewClaudeAdapter`
- `internal/v2/llmtypes/types.go` — `LLMProvider` interface (needs no change, already agnostic)
- `internal/provider/codex.go` — V1 codex provider with correct arg building (reference impl)

## Suggested Fix
1. **Immediate stopgap**: Pin triage to claude in `gromit.yaml` phase_preferences (DONE)
2. **Proper fix**: Create a `codexAdapter` implementing `LLMProvider` with correct codex CLI arg building, and have `run2.go` select the right adapter based on provider config

## Evidence
- `codex --help` confirms `-p` means `--profile <CONFIG_PROFILE>` (Rust clap-style flag)
- `claude --help` confirms `-p` means `--print` (Node.js commander-style flag)
- `codex exec --help` shows codex uses `--json` (not `--output-format json`) and `--model`
- V1 `CodexProvider` in `internal/provider/codex.go` correctly builds args with `exec` subcommand, `--json`, `--model`, `--skip-git-repo-check`, `--color never`
- gromit.yaml routing has `ratio: claude: 10, openai: 90` — 90% of non-pinned phases route to codex
- triage was not pinned, so ~90% of triage calls hit this bug

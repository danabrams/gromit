# Bug Investigation: Codex cost and token tracking returns zero

## Symptom

Bead `gromit-c8tax` (and all other Codex iterations) show `cost_usd: 0` in iteration metrics. Token fields (`input_tokens`, `output_tokens`) are completely absent from JSONL entries — not zero, but missing. This affects all 128 Codex iterations in the metrics file. Claude/sonnet iterations report cost correctly but also lack token fields.

## Root Cause

Three compounding issues:

### 1. Token fields never serialized (all providers)
The `input_tokens` and `output_tokens` fields exist on `logger.IterationLog` (without `omitempty`), and `logging.go:62-63` maps them from `IterationResult`. However, the running binary was built before these fields were added to the logging path. **No iteration in the entire metrics history has token fields.** A rebuild is required.

### 2. Codex CLI doesn't report cost (Codex-specific)
Unlike Claude CLI which includes `total_cost_usd` in stream result events, Codex CLI never emits cost data. The `codexUsage.TotalCostUSD` is always 0. Cost must be estimated client-side from token counts + pricing rates.

### 3. Provider name mismatch in cost estimation fallback (fixed prior to this session)
`estimatedCostUSD()` looked up `r.cfg.Providers[providerName]` using the runtime name `"codex"`, but config keyed the provider as `"openai"`. Fixed by introducing `providerCostDefs` map keyed by `provider.Name()`.

### 4. Pricing was commented out in gromit.yaml (fixed prior to this session)
`cost_per_1k_input` and `cost_per_1k_output` were commented out for both providers. Uncommented and populated.

### 5. No per-model pricing (fixed in this session)
Single provider-level rate doesn't distinguish between high/medium/low tier models (`gpt-5.3-codex` vs `gpt-5.2-codex` vs `gpt-5.3-codex-spark`), which have significantly different pricing.

## Pipeline Verification (preserve_provider_output mode)

With `preserve_provider_output: true` (current config), the stream event handler is `nil`. Token data flows through an alternate path:

1. `processCodexStream()` parses `turn.completed` events, returns `codexUsage` with tokens
2. Codex `StreamRun()` populates `provider.Result.InputTokens/OutputTokens` from usage
3. `invoker.go:164-165` calls `stats.MergeCostData(providerResult.CostUSD, providerResult.InputTokens, providerResult.OutputTokens)`
4. `callbacks.go:80` calls `invResult.Stats.CostData()` which returns the merged values
5. `estimatedCostUSD()` estimates cost from tokens + model-specific pricing

Key detail: `buildStreamCommandArgs()` ignores the handler nil-ness (`_ bool` parameter) and always passes `--json` to codex, so JSONL parsing always occurs. The pipeline is correctly wired.

# Bug Investigation: Codex Low-Tier Never Selected After Crash

## Symptom
Only Claude (haiku) appears to run; Codex low-tier (`gpt-5.1-codex-mini`) is never selected even though `routing.ratio` is set to split traffic between `claude` and `openai`.

## Root Cause
Provider routing uses persisted `provider_counts` from `.gromit/state.json` to maintain configured ratios. The current state file shows a heavily skewed history (`openai: 99`, `claude: 1`) and `clean_exit: false`. The router therefore always selects the most underused provider (claude) until counts rebalance, which can take ~98 iterations. Staleness/crash recovery exists (`CheckStaleness`/`AutoHeal`), but is never invoked during router setup, and `AutoHeal` does not reset provider counts or cooldowns. As a result, a crashed run leaves stale routing counters that lock the router into the same provider for long stretches.

## Affected Code
- `internal/provider/router.go`: `selectByRatio` uses persisted provider counts to choose providers.
- `internal/runner/constructor.go`: loads state file but does not check staleness or auto-heal it.
- `internal/state/state.go`: `AutoHeal()` resets only `IterationsSinceReview` and leaves provider counters/cooldowns intact.
- `.gromit/state.json`: contains `clean_exit: false` and skewed `provider_counts`.

## Suggested Fix
1. When loading `state.json` in `buildRouterAndLearningsProvider`, call `CheckStaleness` using the configured threshold and `AutoHeal` on stale state, then save the healed state.
2. Extend `AutoHeal()` to reset `ProviderCounts` and `ProviderUnavailableUntil` so routing restarts from a neutral baseline after crashes/stale state.
3. Add/adjust tests to cover the new auto-heal behavior and constructor staleness handling.

## Evidence
- `.gromit/state.json` shows `clean_exit: false` and `provider_counts: {"openai": 99, "claude": 1}`.
- Router selection logic chooses the provider with the largest ratio gap; with the above counts and a 50/50 target, it will prefer `claude` until counts rebalance.
- `AutoHeal()` currently only resets `IterationsSinceReview`, leaving provider routing state untouched.

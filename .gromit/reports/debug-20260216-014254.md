# Bug Investigation: Bead timeout on `gromit-evne` despite eventual closure

## Symptom
The latest run failed on bead `gromit-evne` (`Add interactive state pending branch tracking`) with a bead timeout:

- `bead timeout: exceeded 40m0s total processing time`

Observed in:
- `.gromit/logs/run-20260216-002945.jsonl:2`

That run recorded:
- `success=false`
- `validated=true`
- `duration_ms=2449358` (~40m49s)
- `input_tokens=963953`
- `output_tokens=8403`

The bead is now closed in bd, and corresponding commits exist, so this was a runtime timeout during execution, not missing implementation.

## Root Cause
The bead exceeded the configured **per-bead timeout budget** for the model tier used in that run.

Code path:
- Bead context timeout is enforced with `context.WithTimeout` using `Claude.TimeoutsForModel(model).bead_timeout` (`internal/runner/process.go:41-44`).
- On invocation error, if bead context expired while parent context is still active, the failure is classified and returned as bead timeout (`internal/runner/callbacks.go:48-52`).

Config evidence:
- Sonnet model timeout override sets `bead_timeout: 2400` seconds (`gromit.yaml:132-135`) = 40 minutes.
- Run error message is exactly `exceeded 40m0s`.
- Actual duration (`2449358ms`) exceeded this budget.

Contributing factor:
- The run consumed unusually high token volume (`~964k` input tokens), which strongly indicates repeated/large-context retries within one bead attempt, making timeout likely under a fixed 40-minute budget.

## Suggested Fix
1. **Operational guardrail (recommended first):** auto-split/defer when token or retry budget trends indicate likely bead-timeout risk before continuing retries.
2. **Timeout strategy:** make bead timeout adaptive by phase/retry depth (e.g., lower retries for high-token attempts, or early fail when elapsed time leaves insufficient budget for validation).
3. **Prompt/context budget control:** cap retry prompt growth and compress failure context to reduce per-attempt latency/token load.
4. **Optional immediate mitigation:** increase sonnet-tier bead timeout only if higher runtime/cost is acceptable.

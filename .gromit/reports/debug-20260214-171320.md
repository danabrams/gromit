# Bug Investigation: ATDD beads close without implementation due to invisible acceptance tests

## Symptom
Beads with ATDD enabled are being marked as "already done" and closed immediately after acceptance tests are written, without any implementation work occurring. Acceptance criteria are never met.

## Root Cause
The ATDD workflow creates acceptance tests in `*_acceptance_test.go` files. The project's `final_verification_test.go` enforcement rule requires all such files to have `//go:build acceptance` tags. The validation system uses `go test ./...`, which excludes build-tagged tests.

This creates an invisible-test loop:

1. **ATDD Phase 1**: Claude writes acceptance tests, names them `*_acceptance_test.go`
2. Enforcement rule forces `//go:build acceptance` tag on these files
3. **ATDD Phase 2** (`VerifyTestsFail` in `methodology/executor.go:106-134`): Runs `go test ./...` to verify tests fail before implementation
4. `go test ./...` **skips** all `//go:build acceptance` tagged tests
5. Only pre-existing tests run, which all pass
6. `VerifyTestsFail` returns error: "acceptance tests passed before implementation"
7. `VerifyTestsFailWithRetry` (`methodology/refactor.go:336-391`) exhausts retries, returns `ErrATDDAlreadyDone`
8. `processBead` (`runner.go:869-872`) sets `Success=true, AlreadyDone=true`
9. Main loop (`runner.go:702-709`) closes the bead

## Affected Code
- `internal/runner/methodology/executor.go:106-134` — `VerifyTestsFail` uses `e.cfg.Validation.Commands` which is `go test ./...` (no `-tags acceptance`)
- `internal/runner/methodology/refactor.go:336-391` — `VerifyTestsFailWithRetry` returns `ErrATDDAlreadyDone` after failed retries
- `internal/runner/runner.go:868-876` — `processBead` treats `ErrATDDAlreadyDone` as success
- `gromit.yaml:96-99` — validation commands: `go test ./...`, `go vet ./...`, `go build ./...`
- `.gromit/templates/PROMPT_acceptance_tests.md:137` — instructs Claude to use `//go:build acceptance` for tests needing external deps, but Claude applies it to all ATDD tests due to naming convention
- `cmd/gromit/final_verification_test.go` — enforces that `*_acceptance_test.go` files must have `//go:build acceptance`

## Suggested Fix
Two-part fix:

**Part 1 (Template)**: Update `PROMPT_acceptance_tests.md` to explicitly instruct Claude to:
- Write ATDD tests in regular `*_test.go` files (NOT `*_acceptance_test.go`)
- NOT use `//go:build acceptance` tags
- Reserve `*_acceptance_test.go` naming only for true E2E tests needing external dependencies

**Part 2 (Cleanup)**: Delete broken acceptance test files that reference nonexistent code from beads that were incorrectly closed.

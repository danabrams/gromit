# Bug Investigation: Planned specs not appearing in decompose picker

## Symptom
`gromit decompose` reported:

- `No undecomposed plans found. Create one with 'gromit plan'.`

The user expected recently planned specs to appear in the decompose picker and suspected they might exist on remote main or in stale worktrees.

## Root Cause
The decompose picker only scans the current worktree's local plans directory (`.gromit/plans` via `Pipeline.QueryUndecomposedPlans`). It does not query other worktrees or remote branches.

In this worktree, every local plan file is marked `decomposed: true`, so the picker correctly returns zero undecomposed plans.

The expected plans do exist outside the current worktree context:
- Current worktree is behind `origin/main` by 22 commits (`git rev-list --left-right --count HEAD...origin/main` => `3 22`)
- `origin/main` contains undecomposed plan files not present locally in this worktree:
  - `.gromit/plans/spc-special-vs-common-cause-action-policy.md` (`decomposed: false`)
  - `.gromit/plans/vision-metrics-pr-template-and-ci-enforcement.md` (`decomposed: false`)
- Additional stale worktrees contain undecomposed plan copies that are not visible from the current worktree.

## Affected Code
- `cmd/gromit/decompose.go`: `runDecompose` (picker flow)
- `internal/pipeline/pipeline.go`: `QueryUndecomposedPlans`
- `cmd/gromit/resolve.go`: `resolvePlansDir`

## Suggested Fix
Short-term operational fix:
- Sync the current worktree with latest main so local `.gromit/plans` includes newly planned specs.
- Decompose from the same worktree where planning occurred, or merge those plan files first.

Product-level fix (follow-up):
- Improve `gromit decompose` empty-state diagnostics to detect and explain likely causes:
  - branch/worktree behind `origin/main`
  - undecomposed plans present in sibling worktrees
- Offer explicit remediation hints in CLI output.

## Evidence
- Reproduction in current worktree:
  - `go run ./cmd/gromit decompose` => `No undecomposed plans found...`
- Local plan state:
  - 173 plan files in `.gromit/plans`
  - all 173 have `decomposed: true`
- Remote divergence:
  - `git rev-list --left-right --count HEAD...origin/main` => `3 22`
  - `git diff --name-status HEAD..origin/main -- .gromit/plans` shows two added undecomposed plans on remote main
- Stale worktree evidence:
  - Multiple sibling worktrees contain undecomposed plans (`decomposed: false`) not visible from this worktree's picker.

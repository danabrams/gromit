# Bug Investigation: TDD Coverage Tracker Loops Without Progress

## Symptom

The TDD fresh-context orchestrator repeatedly cycles without making any forward progress on coverage criteria. The log shows "TDD coverage tracker reports unchecked criteria after cycle pass N; injecting additional cycles" repeating until `maxOrchestratorPasses` is exhausted, then the bead fails with "tdd fresh-context stopped with unchecked coverage criteria". On retry, a fresh CoverageTracker is created, all progress is lost, and the same loop repeats up to `StuckBeadThreshold` (3) times.

Example from `run-20260221-174742.jsonl`: bead `gromit-nb9pf` ("Implement Build stage with methodology selection and StreamRun") ran for 24+ minutes with ALL 14 criteria remaining unchecked.

## Root Cause

**Two interacting bugs in the red-passes early-exit path:**

### Bug 1: Coverage never updated when red validation passes (callbacks_tdd.go)

When the red phase writes a test and it PASSES (implementation already exists), the `ValidateFn` closure in `callbacks_tdd.go` is called with `lastRenderedPhase == tddPhaseRed`. The coverage validation check at line 141 has this guard:

```go
if !passed || tracker == nil || r.methodologyExec == nil || lastRenderedPhase != tddPhaseGreen {
    return result.Output, passed, nil  // <-- early return, coverage NOT checked
}
```

Since `lastRenderedPhase == "red"` (not "green"), coverage validation is skipped entirely. The criterion stays `Unchecked` in the tracker. The green phase never runs (because tests already pass), so coverage validation never gets a chance to run.

### Bug 2: `state.Done = true` exits inner loop after one cycle (orchestrator.go:180-191)

When red validation passes unexpectedly, `runOneCycle` sets `state.Done = true`:

```go
if passed {
    if err := o.runFinalValidation(ctx); err != nil {
        return err
    }
    state.Done = true                    // <-- kills the inner loop
    *state = AssembleCycleState(*state, "")
    return nil
}
```

`CycleState.IsComplete()` returns true when `Done == true`, so `RunCycles` returns after just ONE cycle per outer pass. Since coverage wasn't updated (Bug 1), the outer loop sees the tracker is incomplete and retries—but each retry runs only one cycle before exiting.

### The Loop

With `maxOrchestratorPasses = 10` and `StuckBeadThreshold = 3`:

1. Pass 1: Red renders, Claude writes test, tests pass → Done=true → RunCycles returns → 0 coverage progress
2. Pass 2: Same thing → 0 coverage progress
3. ... (repeats 10 times)
4. Error: "tdd fresh-context stopped with unchecked coverage criteria"
5. Bead fails. Retried with FRESH tracker (rejection counts lost).
6. Steps 1-4 repeat 2 more times.

**Total: 30 Claude invocations, 30 validation runs, ~60+ minutes, zero progress.**

## Affected Code

- `internal/runner/callbacks_tdd.go:141` — ValidateFn early-return skips coverage when `lastRenderedPhase != tddPhaseGreen`
- `internal/runner/tdd/orchestrator.go:180-191` — `runOneCycle` sets `state.Done = true` when red passes, preventing processing of remaining criteria
- `internal/runner/process_methodology.go:115-130` — outer loop retries without progress because tracker never advances
- `internal/runner/tdd/handoff.go:36-48` — `CycleState.IsComplete()` returns true when `Done == true`

## Suggested Fix

### Change 1: Mark coverage when red validation passes (`internal/runner/callbacks_tdd.go`)

In the `ValidateFn` closure, BEFORE the existing early-return guard (line ~141), add:

```go
// When red-phase tests pass unexpectedly, the implementation already
// covers the pending criterion. Mark it covered so the tracker advances
// instead of looping with no progress.
if passed && tracker != nil && lastRenderedPhase == tddPhaseRed && pendingCoverageCriterion != nil {
    tracker.MarkCovered(pendingCoverageCriterion.Number)
    updateIterationCoverageMetrics(activeBC.Result, tracker)
    pendingCoverageCriterion = nil
    lastRenderedPhase = ""
}
```

### Change 2: Don't kill inner loop when red passes (`internal/runner/tdd/orchestrator.go`)

In `runOneCycle`, change the red-passes branch from:

```go
if passed {
    if err := o.runFinalValidation(ctx); err != nil {
        return err
    }
    state.Done = true
    *state = AssembleCycleState(*state, "")
    return nil
}
```

To:

```go
if passed {
    // Tests pass — criterion is already implemented.
    // Advance to next remaining criterion instead of stopping.
    // AssembleCycleState sets Done=true when Remaining is empty.
    *state = AssembleCycleState(*state, "")
    return nil
}
```

This removes `state.Done = true` (letting the inner loop process all remaining criteria) and removes `runFinalValidation` (redundant—tests already pass, and full validation runs after all TDD cycles complete in `process_methodology.go:140-145`).

### Result After Fix

With 14 criteria and implementations already existing:
- Pass 1: 10 cycles, each marking one criterion as covered (10 covered)
- Pass 2: 4 cycles, each marking one criterion as covered (14 covered)
- Tracker complete → outer loop breaks → bead succeeds
- **Total: 14 Claude invocations (vs 30 wasted invocations before)**

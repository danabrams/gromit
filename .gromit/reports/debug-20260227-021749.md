# Bug Investigation: Lifecycle/Phase Events Not Emitted by Orchestrator Pipeline

## Symptom
The `gromit-ion` bead targets typed lifecycle and phase-event emission across orchestrator and pipeline stages, but runtime flow still relies on direct textual output.

Observed behavior/evidence:
- `internal/runner/orchestrator.go` still emits lifecycle progress through `o.logf(...)` rather than `events.Event` emission.
- Stage packages listed by the bead (`prepare/gate.go`, `execute/build.go`, `review/review.go`, `epilogue/epilogue.go`) still emit textual warnings/progress via `fmt.Fprintf(...)`.
- `StartSubscribers()` starts the CLI subscriber, but without corresponding typed event production, subscriber output remains incomplete and event-system contracts are not fulfilled.

## Root Cause
Root cause is architectural incompleteness, not a single-line bug:

1. Event infrastructure exists (`internal/events/*`, `Orchestrator.emitter`, subscriber startup), but lifecycle and phase boundaries are not wired to publish typed events.
2. Stage APIs do not carry an emitter/event sink in `pipeline.Input`, so stages cannot consistently emit typed events.
3. Legacy text logging is still the primary mechanism in orchestrator and stage boundaries, leaving the event system partially integrated.

This creates a mismatch between intended behavior (typed event stream at run/iteration/phase boundaries) and current implementation (mixed direct output + sparse event support).

## Suggested Fix
Use Outcome 2 (clear fix, non-trivial) and implement with a staged plan:

1. Add event sink/emitter plumbing into pipeline stage input so each stage can emit typed events.
2. Emit typed run/iteration lifecycle events in orchestrator (`RunStart`, `IterationStart`, `IterationComplete`, `RunComplete`, plus bead outcomes).
3. Emit phase boundary events in stages:
- Gate: scope/stuck/skip/block outcomes (typed where available; fallback `LogEvent` for unmapped warnings).
- Build: build start/complete/escalation markers.
- Review: review start/complete + failure mapping.
- Epilogue: bead close/failure/cleanup outcomes.
4. Route any remaining unmapped textual messages through `events.LogEvent` as transition-safe fallback.
5. Add/expand tests that assert emitted event ordering/content at orchestrator+stage boundaries.

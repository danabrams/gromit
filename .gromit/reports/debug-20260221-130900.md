# Bug Investigation: Stale pending_worktree_branches after runner merges interactive branches

## Symptom

`gromit review` (interactive) returned:

```
merge conflict for branch gromit/review-1771677515444216014; manual handoff required in .-gromit-review-1771677515444216014 and pending branch retained
```

This `mergeConflictHandoffError` was surfaced because the review worktree's branch could not be fast-forward merged into main at the time of the interactive session (main had moved ahead while the review was running in its separate worktree).

At investigation time:
- Branch `gromit/review-1771677515444216014` no longer exists (already merged)
- Worktree `.-gromit-review-1771677515444216014` no longer exists (cleaned up)
- `interactive-state.json` still listed both `gromit/debug-1771674676309558925` and `gromit/review-1771677515444216014` as pending

## Root Cause

Two separate mechanisms track pending interactive worktree branches, and they can diverge:

1. **`interactive-state.json` `pending_worktree_branches`**: Updated by `AddPendingWorktreeBranch` (on session start) and `RemovePendingWorktreeBranch` (in `clearMergedState` on successful merge via the interactive session itself).

2. **Runner's `mergeInteractiveBranches()`** (`internal/runner/lifecycle.go:366`): Reads all `gromit/*` git branches via `PendingBranches()`, calls `MergeBack` on each, and on success deletes the branch — but does **not** call `RemovePendingWorktreeBranch` and does **not** call `interactiveWorktreeCleanupSessionFn`.

**What happened:**

1. The interactive review session created branch `gromit/review-1771677515444216014`, ran the review, and committed the review output (`1a8763a8`).
2. `AddPendingWorktreeBranch("gromit/review-1771677515444216014")` was called.
3. `MergeBack` was called — the fast-forward failed because the runner had concurrently committed code to main, creating a diverged HEAD.
4. `mergeConflictHandoffError` was returned; the branch was left in git; the worktree was left on disk; `interactive-state.json` was left with the pending entry.
5. On the runner's **next** between-iteration sweep, `mergeInteractiveBranches()` found the branch and successfully fast-forward merged it (confirmed by reflog: `1a8763a8 refs/heads/main@{0}: merge gromit/review-1771677515444216014: Fast-forward`).
6. `mergeInteractiveBranches` deleted the branch from git but **never updated `interactive-state.json`** and never removed the worktree.
7. The worktree was cleaned up separately (likely by `git worktree prune` or a manual `git worktree remove` during a subsequent session).
8. `interactive-state.json` was left with a stale entry.

The same sequence also affected `gromit/debug-1771674676309558925` (its commit `36ffdaf4` is also confirmed merged in the reflog).

## Affected Code

- `internal/runner/lifecycle.go:366-391` — `mergeInteractiveBranches()`: merges branches found in git but doesn't update `interactive-state.json` or remove worktrees.
- `cmd/gromit/interactive_worktree.go:229-236` — `clearMergedState()`: the correct cleanup path (removes from state AND worktree), but only called from the interactive session's own merge path, not from the runner path.

## Suggested Fix

`mergeInteractiveBranches()` should, after each successful `MergeBack`, also:
1. Remove the branch from `interactive-state.json` via a `pendingBranchRecorder` (the runner already holds `st.interactiveFile` which is an `*state.InteractiveFile` and satisfies `pendingBranchRecorder`).
2. Optionally: remove the worktree if it still exists (via `interactiveWorktreeCleanupSessionFn` or `git worktree remove`). This is more complex because the runner doesn't know the worktree path from the branch name alone. Tracking worktree path in `interactive-state.json` alongside the branch name would enable this.

**Minimal fix** (addresses the state staleness without worktree path tracking):
Pass `st.interactiveFile` into `mergeInteractiveBranches()` and call `RemovePendingWorktreeBranch(branch)` on successful merge.

**Full fix** (addresses both state staleness and orphaned worktrees):
Store `{ branch, worktreeDir }` pairs in `interactive-state.json` instead of just branch names. On successful merge (by either path), remove the entry and clean up the worktree directory.

## Evidence

- `git reflog --all | grep review-1771677`: confirms fast-forward merge
  ```
  1a8763a8 refs/heads/main@{0}: merge gromit/review-1771677515444216014: Fast-forward
  36ffdaf4 refs/heads/main@{1}: merge gromit/debug-1771674676309558925: Fast-forward
  ```
- `git worktree list`: no review worktree present at investigation time
- `git branch -a`: no `gromit/review-1771677515444216014` branch present
- `.gromit/interactive-state.json` at investigation time had both branches listed as pending

## Immediate Fix Applied

Removed both stale entries from `.gromit/interactive-state.json`. The actual code change remains unfixed (tracked below).

# Bug Investigation: gromit-mpwi fails with `claude invocation: context cancelled: context deadline exceeded`

## Symptom
- Reported failure:
  - `FAILED: gromit-mpwi - claude invocation: context cancelled: context deadline exceeded`
  - `bead gromit-mpwi failed: claude invocation: context cancelled: context deadline exceeded`
- Session state notes:
  - `git pull --rebase`, `bd sync`, and `git push` succeeded.
  - `git status` is up to date with `origin/main`.
  - `.gromit/state.json` remains unstaged.

## Root Cause
The bead failed because the **parent run context deadline** expired during the invocation, not because of a logic or compile/test failure in bead `gromit-mpwi`.

In `makeInvokeFn`, when `bc.ParentCtx.Err() != nil`, the code returns `context cancelled: <parent error>`. In this run, that parent error was `context deadline exceeded`, which maps exactly to the surfaced error string.

## Affected Code
- `internal/runner/callbacks.go:52` — parent context cancellation is translated to `context cancelled: %w`.
- `internal/runner/process.go:67` — `ParentCtx` in bead context is set to the run-level context.
- `cmd/gromit/main.go:157` — run-level context gets a deadline when time-budget flags are used.
- `internal/runner/run_init.go:131` — loop checks `ctx.Done()` and exits when parent context is canceled.
- `.gromit/logs/run-20260216-185505.jsonl:5` — iteration record for `gromit-mpwi` shows `error:"claude invocation: context cancelled: context deadline exceeded"`.

## Suggested Fix
No immediate code fix is required to recover this bead; this was deadline exhaustion behavior.

Operational recovery:
- Re-run the bead with a larger budget (or no time-budget deadline), e.g. `gromit run -n 1` with no `--time-budget` flags.

Potential product improvement (follow-up):
- Add a pre-iteration guard that avoids starting a new bead when remaining run budget is below a configured minimum threshold, and emit a dedicated message like `run time budget exhausted before starting next bead` instead of a bead-level failure.

## Evidence
- Run log (`.gromit/logs/run-20260216-185505.jsonl`) shows 4 successful iterations, then iteration 5 fails with parent-context deadline error.
- Failure entry:
  - `bead_id: gromit-mpwi`
  - `duration_ms: 428660`
  - `error: claude invocation: context cancelled: context deadline exceeded`
- Code path analysis confirms this exact message is produced only when `bc.ParentCtx` is canceled.
- `.gromit/state.json` being unstaged is expected runtime metadata behavior and not related to the failure.

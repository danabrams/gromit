# Bug Investigation: CI test job fails before completing test stages

## Symptom
CI `test` job consistently fails. The run sequence is:
1. `make test-parallel-safe-top5`
2. `make test-unit`
3. `make test-acceptance`

Observed failures during reproduction:
- Guard failure: tracked runtime artifacts under `.gromit/benchmarks/results/...`
- Guard failure: shared-state test call guard flags new `os.Chdir(...)` usage
- Unit failure (before fix): `TestPipeline_StartExploreSessionCancelClosesEventChannel` timed out
- Acceptance suite currently has multiple compile/runtime failures in this branch

## Root Cause
There are multiple independent failure sources:

1. Guard-policy violations are present in-repo and fail CI before tests:
   - Runtime benchmark outputs were tracked in git (forbidden by repo hygiene policy)
   - Shared-state guard detects new `os.Chdir` calls not reflected in allowlist

2. A unit test had incorrect closed-channel detection logic:
   - `internal/pipeline/explore_test.go` used a `select { default: ... <-eventsChan }` pattern that can fail even when the channel is correctly closed.
   - This produced deterministic failures in repeated runs.

3. Acceptance suite is currently not green in this branch due to broader drift:
   - API signature mismatches in acceptance tests (`context.Context` args missing)
   - Import-cycle and missing symbol failures in acceptance-tagged packages
   - Additional assertion/template-path failures in acceptance tests

## Suggested Fix
Immediate:
- Keep the unit-test fix to `TestPipeline_StartExploreSessionCancelClosesEventChannel` (already applied in this session).
- Remove tracked runtime benchmark artifacts from git history going forward (already removed in this session).

Follow-up (non-trivial, cross-cutting):
- Resolve shared-state guard violation in `cmd/gromit/test_binary_helpers_test.go`:
  - Prefer replacing `os.Chdir` with isolation seams; only allowlist if unavoidable with rationale.
- Repair acceptance suite API drift:
  - Update acceptance tests to new bead client signatures requiring `context.Context`.
  - Fix acceptance-tag build/import issues (`test/contracts`, `test/e2e`, `internal/provider` cycle).
  - Fix retro/runner acceptance path assumptions (template location and output expectations).

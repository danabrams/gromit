# Bug Investigation: run2 worktree commits not reaching spec branches

## Symptom

User reports run2 appears to be committing to main rather than creating spec PRs. The spec vision (documented in `.gromit/specs/branch-per-spec.md`, `spec-pr-review-gate.md`, and `v2-run-loop.md`) requires each spec to get its own branch (`gromit/spec-<name>`) with a GitHub PR targeting main.

## Root Cause

The `ExecGitAdapter.Checkout` creates a **detached HEAD worktree** but never creates or pushes a named spec branch. The full flow:

1. `Checkout` runs `git worktree add <path> HEAD` (detached HEAD)
2. Bead loop commits work into the detached worktree
3. `GitHubPresenter.PresentSummary` calls `gh pr create --head gromit/spec-<name>` — but this branch **does not exist** on the remote
4. `cleanupWorktree` removes the worktree (and its detached commits)

Result: commits are made in an ephemeral worktree that references no named branch, the PR creation fails (or silently errors), and the worktree is deleted. Work is either lost or falls back to some other path that commits to main.

## Affected Code

- `internal/v2/adapter/git/exec_git_adapter.go:30-43` — `Checkout` creates detached HEAD worktree
- `internal/v2/adapter/git/git.go` — `GitAdapter` interface lacks `CreateBranch` and `Push` operations
- `internal/v2/adapter/presenter/github.go:86-97` — `PresentSummary` assumes spec branch exists on remote
- `internal/v2/loop/spec_loop.go:195-198` — Checkout call site
- `internal/v2/loop/spec_loop.go:275-277` — Present call site (just before worktree removal)

## Suggested Fix

The GitAdapter interface and ExecGitAdapter need three new capabilities:

1. **`Checkout` should create a named branch** — change from `git worktree add <path> HEAD` to `git worktree add -b gromit/spec-<specID> <path> HEAD`
2. **Add `Push` method** — `git push -u origin gromit/spec-<specID>` before PR creation
3. **SpecLoop wiring** — after bead loop completes and before `presentSummary`, push the spec branch

The `SpecLoop.Run` flow should become:
1. `Checkout` (creates worktree on named branch `gromit/spec-<specID>`)
2. Plan, Decompose, Bead Loop (commits land on named branch)
3. Accept
4. **Push branch to remote** (new step)
5. Present (creates/updates PR — branch now exists on remote)
6. Cleanup worktree (branch persists on remote even after worktree removal)

## Evidence

- `exec_git_adapter.go:36`: `git worktree add <path> HEAD` — no `-b` flag, detached HEAD
- `github.go:88-90`: `gh pr create --head <branch>` assumes branch exists
- `git.go` interface: only Checkout/Diff/Commit/RemoveWorktree/Status — no Push, no CreateBranch
- Spec vision docs (`spec-pr-review-gate.md`) explicitly require: "Push the gromit/spec-<name> branch to origin" and "Create a GitHub PR via gh pr create"
- `presentation/summary.go`: `SpecBranchName()` generates `gromit/spec-<specID>` — naming is correct, but the branch is never actually created

# Bug Investigation: TDD Coverage Loop — Spec-Level Criteria Applied to Individual Beads

## Symptom
Gromit loops endlessly (or for 30-40 minutes per bead) in TDD fresh-context cycles. The user sees "work is done but keeps going." Individual beads that implement a single pipeline stage cycle through all 14 spec-level acceptance criteria from the `runner-pipeline` spec, wasting Claude invocations on irrelevant criteria.

## Root Cause
`buildCoverageTrackerFromSpec()` in `internal/runner/process_methodology.go:151` loads ALL spec-level criteria for every individual bead when methodology granularity is `"bead"` (the default). The function only skips when granularity is `"spec"` — the logic is inverted from the correct behavior.

**The problem chain:**
1. Granularity defaults to `"bead"` (gromit.yaml line 239, commented out)
2. `buildCoverageTrackerFromSpec` returns a tracker with all 14 spec criteria for each bead
3. `resolveInitialCycleState` replaces the bead's own `ExpectedOutputs` with the 14 spec criteria
4. The TDD orchestrator runs a red phase for EACH criterion (~2-3 min each)
5. Most criteria are system-level ("go build passes", "all 5 stages compile") that no single bead can satisfy
6. Each criterion goes through: red-pass → mark covered (after fix 903c5e06) or 2 rejections → untestable
7. This wastes 28-42 minutes per bead on irrelevant criteria before reaching the bead's actual work

**Evidence from logs:**
- Run 174742: `gromit-nb9pf` (Build stage) — 14 criteria total, 0 covered → "tdd fresh-context stopped with unchecked coverage criteria"
- Run 192727: `gromit-iqoj4` (Epilogue) — 14 criteria total, 13 covered via red-pass, timed out on criterion 14
- Current run 195037: 6+ invocations in 20 min (cycling through criteria)

## Affected Code
- `internal/runner/process_methodology.go:151-175` — `buildCoverageTrackerFromSpec()`: loads spec criteria when it should return nil for bead granularity
- `internal/runner/callbacks_tdd.go:214` — `resolveInitialCycleState()`: replaces bead ExpectedOutputs with spec criteria when tracker is non-nil

## Fix Applied
Changed `buildCoverageTrackerFromSpec()` to always return nil — disabling per-bead spec-criteria tracking. This is correct because:
- Spec-level criteria are system-level and cannot be satisfied by individual beads
- The spec gate (which runs after all beads complete) handles system-level criteria
- When tracker is nil, TDD cycles use the bead's own ExpectedOutputs directly
- The outer loop runs exactly one pass and breaks (since `coverageTracker == nil`)

Updated 8 tests to match the new behavior:
- `process_methodology_unit_test.go`: 6 tests updated
- `process_methodology_dirty_tree_test.go`: 1 test updated

# Bug Investigation: Refactor Re-validation Fails on Bead Timeout Budget

## Symptom
Validation failed after refactoring with:
`validation after refactoring aborted due to timeout budget exhaustion: validation command "go test -vet=off -short -p 4 -parallel 4 ./internal/runner/... ./test/contracts/... ./test/fixtures/..." aborted: context deadline exceeded`

This occurs after the main build/validation path, during the optional refactor + post-refactor validation stage.

## Root Cause
The refactor post-check path always runs a second validation pass when ATDD/TDD is active. That second pass uses the same bead-scoped context and can start when little time remains in the bead timeout budget.

When the parent bead context expires mid-command, validation returns an "aborted" error (`validation command ... aborted: context deadline exceeded`) rather than a normal validation failure. The runner then wraps that as a hard terminal bead error (`validation after refactoring aborted due to timeout budget exhaustion`) and fails the bead.

In short: optional refactor verification is currently not guarded by remaining time budget, so it can fail otherwise-successful beads near the deadline.

## Affected Code
- `internal/runner/process_methodology.go:127` — `runRefactorAndPostChecks` always runs refactor phase, then always runs validation again when enabled.
- `internal/runner/validation/runner.go:189` — expired parent context is surfaced as `validation command ... aborted: context deadline exceeded`.
- `internal/runner/runner.go:229` — wraps deadline errors as `validation after refactoring aborted due to timeout budget exhaustion`.
- `internal/config/config.go:551` — command scoping can expand `go test ./...` into multiple touched-package globs, which may still be expensive near deadline.
- `gromit.yaml:102` — fast gate runs `go test -short ... ./...`, then scoping rewrites package list.
- `gromit.yaml:126` and `gromit.yaml:135` — bead budget limits (`bead_timeout`) bound all build + retry + analysis + refactor + re-validation work.

## Suggested Fix
Add an explicit remaining-budget guard for optional refactor post-checks, mirroring the existing review-stage guard behavior.

Recommended behavior:
- Before running refactor phase, check `ctx.Deadline()` / remaining bead budget.
- If remaining time is below a conservative threshold for refactor + re-validation, skip refactor/post-checks and preserve the already validated build result.
- Keep current behavior for genuine non-timeout validation failures.

This is a policy-level behavior choice (what minimum budget is required before optional refactor work), so it should be implemented via a planned change rather than a quick one-liner.

## Evidence
- Error path from user report matches `context deadline exceeded` handling in `internal/runner/validation/runner.go:189`.
- Terminal message matches wrapper logic in `internal/runner/runner.go:233`.
- Refactor + second validation are unconditional in `internal/runner/process_methodology.go:127` and `internal/runner/process_methodology.go:137` when methodology/refactor path is entered.
- Scoped command expansion behavior is implemented in `internal/config/config.go:551` and can produce multi-package command lists like the reported `./internal/runner/... ./test/contracts/... ./test/fixtures/...`.
- Existing codebase precedent for deadline-aware skipping exists in review code (`internal/runner/reviewpkg/reviewer.go:130` and `internal/runner/reviewpkg/reviewer.go:335`).

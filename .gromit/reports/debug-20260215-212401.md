# Bug Investigation: Validation timeout reported after refactor on gromit-2v88

## Symptom
`gromit run` failed on bead `gromit-2v88` with:

- `validation failed after refactoring: validation command "go test ./...": context deadline exceeded`

Observed run log entry:
- `.gromit/logs/run-20260215-204648.jsonl:1`

## Root Cause
The timeout is most likely a **bead-level context deadline**, not a `go test` command-specific timeout.

Evidence in code:
- `Run()` creates a per-bead context with timeout from `claude.bead_timeout` (`internal/runner/process.go:42`).
- Validation commands run using the parent bead context unless `validation.command_timeout` is explicitly configured (`internal/runner/validation/runner.go:169-173`).
- On any context deadline, validation currently classifies it as validation failure and wraps it as `validation command ... context deadline exceeded` (`internal/runner/validation/runner.go:178-185`).
- In refactor mode, this is wrapped again as `validation failed after refactoring` (`internal/runner/runner.go:955-957`).

The failed iteration duration was `1,879,123ms` (~31m19s), which exceeds configured `claude.bead_timeout: 1800` seconds (30m) in `gromit.yaml:125`. That strongly indicates the bead budget was exhausted before/during the post-refactor validation step.

## Affected Code
- `internal/runner/process.go:42`
- `internal/runner/validation/runner.go:169`
- `internal/runner/validation/runner.go:178`
- `internal/runner/runner.go:955`
- `.gromit/logs/run-20260215-204648.jsonl:1`
- `gromit.yaml:125`

## Suggested Fix
1. Distinguish timeout origin in validation:
- If parent bead context (`ctx`) is already deadline exceeded/canceled, return a bead-timeout/cancellation error (not `ErrValidationFailed` command timeout).
- Reserve `ErrValidationFailed` timeout formatting for explicit `validation.command_timeout` expirations.

2. Improve user-facing error message at refactor re-validation boundary:
- Surface whether timeout came from bead budget exhaustion vs command timeout.

3. Optional operational mitigation:
- Configure `validation.command_timeout` explicitly (for deterministic command-level limits) and/or increase `claude.bead_timeout` for methodology-heavy beads.

# Bug Investigation: Claude CLI runs in main repo instead of spec worktree

## Symptom

PR creation fails with "No commits between main and gromit/spec/immutable-pipeline" despite 24 iterations of work completing.

Full error:
```
running spec immutable-pipeline: present failure summary: present summary: create pr: pull request create failed: GraphQL: No commits between main and gromit/spec/immutable-pipeline (createPullRequest): exit status 1
```

## Root Cause

The Claude CLI process launched by the build stage runs in the main repo root instead of the spec worktree. All code changes from 24 iterations went to the wrong directory.

**The chain of failure:**

1. `run2.go:92` — Git adapter created with `repoRoot = "."` (main repo CWD)
2. `exec_git_adapter.go:46` — `Checkout` creates worktree at `.gromit/spec-worktrees/immutable-pipeline` on branch `gromit/spec/immutable-pipeline`
3. `bead_loop.go:555` — `Request.Worktree` is correctly set to the worktree path
4. `build.go:233` — `invokeWithEscalation` does NOT forward worktree to the LLM request
5. `claude.go:335` — `StreamRun` creates `exec.Command` without setting `cmd.Dir`
6. Claude CLI inherits process CWD (main repo root), writes all code there
7. `stage_committer.go:23` — `CommitStage` checks `git status` in the worktree, finds no changes, skips
8. Spec branch stays at same commit as main — PR creation fails

**Evidence:** `git log main..gromit/spec/immutable-pipeline` returns empty — zero commits ahead of main. The merge-base equals the spec branch tip (`fd212cfb`).

## Affected Code

- `internal/v2/llmtypes/types.go:17-22` — `LLMStreamInvokeRequest` has no `Dir`/`Worktree` field
- `internal/v2/stage/build/build.go:233` — `invokeWithEscalation` doesn't pass worktree
- `internal/v2/stage/build/build.go:394` — `StreamInvoke` call omits worktree
- `internal/v2/adapter/llm/claude.go:65-98` — `StreamInvoke` doesn't set `cmd.Dir`
- `internal/claude/claude.go:315-355` — `StreamRun` doesn't set `cmd.Dir`

Also affected (same pattern, non-streaming):
- `internal/v2/adapter/llm/claude.go:38-63` — `Invoke` / `runOnce` doesn't set `cmd.Dir`

## Suggested Fix

Thread a `Dir` field through the LLM invocation chain so the Claude CLI runs in the spec worktree:

1. Add `Dir string` to `LLMStreamInvokeRequest` and `LLMInvokeRequest`
2. Pass `req.Worktree` from `build.Stage.Run` through `invokeWithEscalation` to the invoke request
3. Thread `Dir` through `claude.Client.StreamRun` → set `cmd.Dir` on the exec.Command
4. Thread `Dir` through `claudeAdapter.runOnce` → set `cmd.Dir` on the exec.Command
5. Update all other stages that invoke the LLM (review, accept, plan, triage, decompose) to pass worktree similarly

## Evidence

- `git log main..gromit/spec/immutable-pipeline` → empty (zero unique commits)
- `git merge-base main gromit/spec/immutable-pipeline` → `fd212cfb` (same as spec branch HEAD)
- `git log gromit/spec/immutable-pipeline..main` → 10+ commits (main is ahead)
- `LLMStreamInvokeRequest` struct has only `Prompt`, `Model`, `Output`, `Metadata` — no directory field
- `claude.go:335` — `cmd := execCommandContext(ctx, c.binary, args...)` — no `cmd.Dir` assignment
- `exec_git_adapter.go:10` — `runGitCommand` correctly sets `cmd.Dir = dir` for git operations
- `stage_committer.go:27` — skips commit when `git status` is empty (correct behavior, but the changes are in the wrong tree)

# Provider-Neutral Wording Implementation Plan

**Goal:** Remove provider-specific wording from generic user-facing runtime messages so output consistently refers to the active agent.

**Architecture:** Apply narrowly scoped wording updates in runner heartbeat and escalation handler message paths, keeping Claude-specific configuration/help text and internal Claude identifiers unchanged.

**Tech Stack:** Go (`internal/runner` packages), existing `go test` suite

**Spec:** `.gromit/specs/provider-neutral-wording.md`

---

## Architecture

**Overview:**  
Use a minimal wording-only change set in runtime messaging paths that are provider-generic. Replace generic "Claude"/`claude` references with "agent" where users may run different providers, while preserving intentionally Claude-specific text and implementation symbols.

**Key Components:**
1. **Heartbeat formatting (`internal/runner/execution/heartbeat.go`)**: Neutralize waiting-status wording shown before tool calls.
2. **Escalation retry handler (`internal/runner/escalation/handler.go`)**: Neutralize generic invocation error wording used for any provider.
3. **Runner tests (`internal/runner/execution/heartbeat_test.go`, `internal/runner/escalation/handler_test.go`)**: Confirm wording updates and prevent regression.

**Integration Points:**
- Runtime status output generated by heartbeat routines.
- Runtime failure surfaces in escalation retry loop.
- Existing command help and config semantics in `cmd/gromit` remain untouched.

**Data Flow:**
- Invocation and heartbeat execution flow is unchanged.
- Only final human-readable strings emitted by the same code paths change from Claude-specific to provider-neutral text.

**Files to Modify:**
- `internal/runner/execution/heartbeat.go` - Replace generic waiting text with "agent".
- `internal/runner/escalation/handler.go` - Replace generic invocation/nil-result error text with "agent".
- `internal/runner/execution/heartbeat_test.go` - Add/update string assertions if needed.
- `internal/runner/escalation/handler_test.go` - Add/update string assertions if needed.

**Files to Create:**
- None.

**Tradeoffs:**
- **Targeted literal updates over refactor:** Lower risk and fastest path for a wording-only spec.
- **Update generic runtime errors in escalation:** Ensures provider-neutral UX consistency beyond heartbeat text while still leaving Claude-specific help/implementation references intact.

## Test Strategy

**Test Levels:**
1. **Unit Tests:** Validate updated heartbeat and escalation wording in existing test suites.
2. **Package-Level Verification:** Run targeted `go test` on modified runner packages.
3. **Manual Spot Check:** Ensure Claude-specific CLI help text remains unchanged by confirming no edits in `cmd/gromit` help strings.

**Key Test Cases:**
- Heartbeat with zero tool calls outputs: "Waiting for agent to respond (may be thinking)...".
- Overwrite heartbeat path uses the same updated waiting wording.
- Invocation failure wrap returns `agent invocation: <error>`.
- Nil invocation result failure returns `agent returned nil result`.

**Mocking Strategy:**
- Reuse existing mocks (`mockOverwriteWriter`, handler test scaffolding).
- No new provider or runner fakes required.

**Coverage Goals:**
- Cover both heartbeat string-generation sites (`PrintHeartbeat`, `overwriteHeartbeat`).
- Cover all generic escalation string sites currently emitting `claude` literals.
- Confirm no regression in unrelated behavior (retry logic, timeout handling, escalation decisions).

**Test Organization:**
- Keep assertions in existing files:
  - `internal/runner/execution/heartbeat_test.go`
  - `internal/runner/escalation/handler_test.go`
- Favor focused test additions over broad rewrites.

## Implementation Tasks

### Task 1: Neutralize Heartbeat Waiting Message

**Files:**
- Modify: `internal/runner/execution/heartbeat.go`
- Test: `internal/runner/execution/heartbeat_test.go`

**What to Do:**
Update heartbeat waiting-status strings used before any tool calls so they refer to "agent" rather than "Claude" in both standard print and overwrite-update paths. Add or adjust tests if current coverage does not assert the literal output.

**Acceptance Criteria:**
- `PrintHeartbeat` waiting message uses "Waiting for agent to respond (may be thinking)...".
- `overwriteHeartbeat` waiting message uses the same provider-neutral text.
- Heartbeat package tests pass.

**Dependencies:**
- None.

**Notes:**
- Keep timing/stall logic unchanged; this task is wording-only.

### Task 2: Neutralize Generic Escalation Invocation Errors

**Files:**
- Modify: `internal/runner/escalation/handler.go`
- Test: `internal/runner/escalation/handler_test.go`

**What to Do:**
Replace generic user-facing invocation error strings that currently reference `claude` with provider-neutral `agent` wording in the retry loop error paths. Update tests if they assert the old literals.

**Acceptance Criteria:**
- Invocation failure error prefix is `agent invocation:`.
- Nil invocation result errors use `agent returned nil result`.
- Escalation handler tests pass without behavioral regressions.

**Dependencies:**
- Task 1 can run in parallel; no hard dependency.

**Notes:**
- Do not alter internal type names, config fields, or Claude-specific operational messages that describe Claude CLI facts.

### Task 3: Verify Non-Goals and Run Focused Quality Gates

**Files:**
- Verify unchanged: `cmd/gromit/debug.go`, `cmd/gromit/explore.go`
- Run tests: runner execution/escalation packages

**What to Do:**
Confirm no edits were made to intentionally Claude-specific help text. Run targeted tests for modified packages (and broader tests if needed) to ensure all acceptance criteria hold.

**Acceptance Criteria:**
- Claude-specific help text remains unchanged.
- Targeted `go test` commands for touched packages pass.
- No unrelated message or behavior regressions are introduced.

**Dependencies:**
- Task 1
- Task 2

**Notes:**
- If broader suite failures occur, triage whether they are pre-existing or introduced by this change.

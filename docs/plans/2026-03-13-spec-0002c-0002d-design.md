# Spec 0002c/0002d Design — Provider-Agnostic Adapter Layer & Multi-Provider Routing

Date: 2026-03-13

## Overview

Two specs that wire real LLM providers into the gromit-next execution pipeline, replacing the noop implementations created in 0002a/0002b.

- **0002c** builds a provider-agnostic adapter layer and proves it with Claude.
- **0002d** adds multi-provider routing via the Router, enabling Codex (and future providers) as alternatives.

## Architecture

### Three-Layer Design

```
Pipeline Stages (specloop/stages/)
        │
        ▼
Per-Domain Adapters (planner/, review/, acceptor/, specloop/, validator/)
        │
        ▼
Shared LLMAdapter (llmadapter/)
        │
        ▼
provider.Provider (provider/)
```

Each layer has a single responsibility:

1. **Pipeline stages** — orchestration, state transitions, replan logic (already built in 0002a/0002b)
2. **Per-domain adapters** — parse provider output into domain types (findings, plans, criteria)
3. **Shared LLMAdapter** — invoke provider, enforce timeout, track cost
4. **Provider** — CLI execution, streaming, error detection (already built in 0001)

Adding a new provider requires only implementing `provider.Provider`. No changes to domain adapters or stages.

## Spec 0002c — Provider-Agnostic Adapter Layer

### Package: `internal/next/llmadapter/`

Thin shared base wrapping `provider.Provider`:

```go
type Config struct {
    Tier    string
    Timeout time.Duration
    OnCost  func(cost float64)
}

type LLMAdapter struct {
    provider provider.Provider
    cfg      Config
}

func New(p provider.Provider, cfg Config) *LLMAdapter

func (a *LLMAdapter) Invoke(ctx context.Context, prompt string) (*provider.Result, error)
func (a *LLMAdapter) InvokeStream(ctx context.Context, prompt string, w io.Writer,
    handler provider.EventHandler, onToolCall provider.ToolCallHandler) (*provider.Result, error)
func (a *LLMAdapter) ProviderName() string
func (a *LLMAdapter) Tier() string
```

**`Invoke` flow:**

1. Apply timeout to ctx if configured.
2. Call `provider.Run(ctx, prompt, tier)`.
3. If result has cost, call `OnCost` callback.
4. Return result.

No retry logic — retry strategies differ per domain and belong in the caller.

### Per-Domain Adapters

Each domain package gets a thin adapter (~20-40 lines) that composes `LLMAdapter` and parses output into domain types.

#### `planner.ProviderPlanAgent`

```go
// internal/next/planner/provider_agent.go
type ProviderPlanAgent struct {
    llm *llmadapter.LLMAdapter
}

func (a *ProviderPlanAgent) Invoke(ctx context.Context, prompt, tier string) (AgentResult, error) {
    result, err := a.llm.Invoke(ctx, prompt)
    if err != nil { return AgentResult{}, err }
    return AgentResult{
        Output:    result.Output,
        TokensIn:  result.TokensIn,
        TokensOut: result.TokensOut,
        Cost:      result.Cost,
    }, nil
}
```

Satisfies `planner.Agent`. The `tier` param is ignored — tier is baked into the LLMAdapter. Callers should ensure the tier passed to `Invoke` matches the tier configured on the `LLMAdapter`. A mismatch will be logged as a warning. Existing retry-on-parse-error logic in `Planner.CreatePlan()` is unchanged.

#### `review.ProviderReviewAgent`

```go
// internal/next/review/provider_agent.go
type ProviderReviewAgent struct {
    llm *llmadapter.LLMAdapter
}

func (a *ProviderReviewAgent) ReviewFacet(ctx context.Context, facetName, prompt string) ([]Finding, error) {
    result, err := a.llm.Invoke(ctx, prompt)
    if err != nil { return nil, err }
    raw := extractJSON(result.Output)
    var findings []Finding
    if err := json.Unmarshal([]byte(raw), &findings); err != nil { return nil, fmt.Errorf("parse findings: %w", err) }
    return findings, nil
}
```

Satisfies `review.ReviewAgent`.

#### `acceptor.ProviderAcceptAgent`

```go
// internal/next/acceptor/provider_agent.go
type ProviderAcceptAgent struct {
    llm *llmadapter.LLMAdapter
}

func (a *ProviderAcceptAgent) EvaluateCriterion(ctx context.Context, prompt string) (CriterionResult, error) {
    result, err := a.llm.Invoke(ctx, prompt)
    if err != nil { return CriterionResult{}, err }
    return ParseCriterionResult(result.Output)
}
```

Satisfies `acceptor.AcceptAgent`.

#### `specloop.ProviderTaskRunner`

```go
// internal/next/specloop/provider_taskrunner.go
type ProviderTaskRunner struct {
    llm *llmadapter.LLMAdapter
}

func (r *ProviderTaskRunner) RunTask(ctx context.Context, task runstore.Task) (TaskResult, error) {
    prompt := renderTaskPrompt(task)
    result, err := r.llm.Invoke(ctx, prompt)
    // map result to TaskResult
}

func (r *ProviderTaskRunner) RepairTask(ctx context.Context, task runstore.Task, failures []string) (TaskResult, error) {
    prompt := renderRepairPrompt(task, failures)
    result, err := r.llm.Invoke(ctx, prompt)
    // map result to TaskResult
}
```

Satisfies `specloop.TaskRunner`.

### Non-LLM Stage Implementations

#### Compile: `ContextPktCompiler`

```go
// internal/next/contextpkt/compiler.go
type ContextPktCompiler struct {
    specPath string
    // config for context assembly
}

func (c *ContextPktCompiler) Compile(ctx context.Context) (string, error) {
    // deterministic context packet assembly, no LLM
}
```

Satisfies `stages.SpecCompiler`. Purely deterministic — assembles spec + context packets from files.

#### Validate: `ShellValidator`

```go
// internal/next/validator/shell_validator.go
type ShellValidator struct {
    runner *Runner              // existing shell check runner
    llm    *llmadapter.LLMAdapter  // for failure diagnosis only
}

func (v *ShellValidator) RunFinal(ctx context.Context, alwaysRun, projectChecks []Check, workDir string) (FinalResult, error) {
    result, err := v.runner.RunFinal(ctx, alwaysRun, projectChecks, workDir)
    if err != nil { return FinalResult{}, err }
    if result.Pass { return result, nil }
    diagnosis, _ := v.llm.Invoke(ctx, renderDiagnosisPrompt(result.Failures))
    result.Diagnosis = diagnosis.Output
    return result, nil
}
```

Satisfies `stages.FinalValidator`. Composes the existing `validator.Runner` for shell execution — no LLM for passing checks. On failure, feeds stderr/stdout to LLM for diagnosis.

### Stage-to-Adapter Summary

| Stage | LLM needed? | Adapter |
|-------|-------------|---------|
| Compile | No | `ContextPktCompiler` — deterministic |
| Plan | Yes | `ProviderPlanAgent` → `LLMAdapter` → `provider.Provider` |
| Execute | Yes | `ProviderTaskRunner` → `LLMAdapter` → `provider.Provider` |
| Validate | Shell + LLM on failure | `ShellValidator` — shell-first, LLM for diagnosis |
| Review | Yes | `ProviderReviewAgent` → `LLMAdapter` → `provider.Provider` |
| Accept | Yes | `ProviderAcceptAgent` → `LLMAdapter` → `provider.Provider` |
| Init, Evidence, Finalize | No | Already have real or near-real implementations |

### Wiring: `RealStageProvider` Changes

`cmd/gromit-next/stage_provider.go` changes from noops to real adapters:

```go
func (p *RealStageProvider) BuildStages(policy execpolicy.Policy, rs *runstore.RunState, budget *specloop.Budget) ([]specloop.Stage, error) {
    // 0002c hardcodes Claude; 0002d replaces with Router
    claudeProvider := claude.NewProvider(claude.Config{...})

    costCallback := func(c float64) { budget.AddCost(c) }

    planAdapter := llmadapter.New(claudeProvider, llmadapter.Config{
        Tier: policy.Models.Planner, OnCost: costCallback,
    })
    execAdapter := llmadapter.New(claudeProvider, llmadapter.Config{
        Tier: policy.Models.Executor, OnCost: costCallback,
    })
    reviewAdapter := llmadapter.New(claudeProvider, llmadapter.Config{
        Tier: policy.Models.Evaluator, OnCost: costCallback,
    })
    validateAdapter := llmadapter.New(claudeProvider, llmadapter.Config{
        Tier: provider.TierLow, OnCost: costCallback,
    })

    compileStage := stages.NewCompileStage(
        contextpkt.NewCompiler(p.cfg.SpecPath), store, nil)
    planStage := stages.NewPlanStage(
        planner.NewProviderPlanAgent(planAdapter), store, nil)
    executeStage := stages.NewExecuteStage(
        specloop.NewProviderTaskRunner(execAdapter), ...)
    validateStage := stages.NewValidateStage(
        validator.NewShellValidator(validateAdapter), ...)
    reviewStage := stages.NewReviewStage(
        review.NewProviderReviewRunner(reviewAdapter), ...)
    acceptStage := stages.NewAcceptStage(
        acceptor.NewProviderAcceptEvaluator(reviewAdapter), ...)
    // ...
}
```

One provider, multiple adapters at different tiers. All feed cost back to the shared Budget.

## Spec 0002d — Multi-Provider Routing

### Router Wiring

Replace hardcoded Claude with Router in `RealStageProvider`:

```go
// Note: actual NewRouter signature takes positional params — see provider/router.go
router := provider.NewRouter(
    loadProviders(policy),        // providers map[string]Provider
    policy.Routing.Preferences,   // preferences map[string]string
    policy.Routing.Ratio,         // ratio map[string]int
    policy.Routing.Cooldown,      // cooldown time.Duration
    stateFileFn,                  // stateFn StateFile
)

planProvider, _ := router.Select("plan", policy.Models.Planner)
planAdapter := llmadapter.New(planProvider, llmadapter.Config{
    Tier: policy.Models.Planner, OnCost: costCallback,
})
// ... same pattern for exec, review, validate
```

> **Note:** `policy.Routing` config will need to be added to `execpolicy.Policy` as part of 0002d implementation.

### Fallback on Usage-Limit

Optional wrapper that satisfies the `Invoker` interface — domain adapters are unaware of fallback:

```go
// internal/next/llmadapter/fallback.go
type FallbackAdapter struct {
    primary *LLMAdapter
    router  *provider.Router
    phase   string
    cfg     Config  // stored so fallback adapter inherits primary's config
}

func (f *FallbackAdapter) Invoke(ctx context.Context, prompt string) (*provider.Result, error) {
    result, err := f.primary.Invoke(ctx, prompt)
    if err != nil && f.primary.provider.IsUsageLimitError(result, err) {
        f.router.MarkUnavailable(f.primary.ProviderName())
        fallbackProvider, _ := f.router.Select(f.phase, f.primary.Tier())
        if fallbackProvider == nil { return result, fmt.Errorf("all providers unavailable: %w", err) }
        fallback := New(fallbackProvider, f.cfg)
        fallbackResult, fallbackErr := fallback.Invoke(ctx, prompt)
        if fallbackErr != nil { return fallbackResult, fmt.Errorf("primary provider %s hit usage limit, fell back to %s: %w", f.primary.ProviderName(), fallback.ProviderName(), fallbackErr) }
        return fallbackResult, nil
    }
    return result, err
}
```

### Bridging 0002c and 0002d: `ProviderAwareInvoker`

0002c must define a `ProviderAwareInvoker` interface that extends `Invoker` with `Provider() provider.Provider`, along with a `NewProviderAware()` constructor. Alternatively, `LLMAdapter` must expose its underlying provider via a public method. This is required so that 0002d's `FallbackAdapter` and Router integration can inspect and swap providers without breaking the adapter abstraction.

### Codex-Specific Work

The `provider.CodexProvider` already exists with stdin prompt delivery, JSONL streaming, `--full-auto` flags, and tier-to-model mapping. 0002d work is:

1. **Prompt compatibility** — verify existing prompts produce parseable output from Codex.
2. **Contract tests against Codex** — must pass (hard gate).
3. **Provider-specific prompt tuning** — if needed, add prompt wrappers in domain adapters.

### What 0002d Does NOT Do

- No new adapter interfaces.
- No changes to domain packages.
- No new stage types.

It is purely operational: Router wiring + fallback + Codex validation.

## Testing Strategy

### Test Matrix

| Test type | CI | Local | Provider | Gate? |
|-----------|-----|-------|----------|-------|
| Unit (mock provider) | Yes | Yes | Mock | Yes — must pass |
| Contract (structural) | No | Yes | Real Claude/Codex | Yes — must pass locally |
| Integration scenarios | No | Manual | Real Claude/Codex | No — prepared, not blocking |

### Unit Tests (CI)

**`llmadapter/` unit tests:**
- `Invoke` calls `provider.Run` with correct tier
- Timeout enforcement cancels ctx
- `OnCost` callback fires with result cost
- Error propagation from provider

**Per-domain adapter tests:**
- Each adapter with mock provider
- Verify correct parsing: `ParsePlan`, `ParseFindings`, `ParseCriterionResult`
- Verify prompt rendering for TaskRunner (RunTask, RepairTask)
- ShellValidator: passing checks → no LLM call; failing checks → LLM called

**Integration tests (`cmd/gromit-next/`):**
- `RealStageProvider.BuildStages` returns stages with real adapters
- End-to-end with mock provider: full pipeline through all stages

### Contract Tests (Local Only)

Gated by env var (e.g., `GROMIT_LLM_CONTRACT=1`). Never run in CI.

Each agent interface gets a contract test suite that runs against every real provider:

```go
func RunReviewAgentContract(t *testing.T, agent ReviewAgent) {
    t.Run("returns valid findings for well-formed prompt", ...)
    t.Run("returns empty findings not nil for clean code", ...)
    t.Run("findings have required fields (severity, message, location)", ...)
    t.Run("handles empty prompt gracefully", ...)
    t.Run("respects context cancellation", ...)
}
```

Same pattern for:
- `planner.RunPlanAgentContract(t, agent)` — plan has tasks, tasks have objectives
- `acceptor.RunAcceptAgentContract(t, agent)` — result has pass/fail/unclear, rationale non-empty
- `specloop.RunTaskRunnerContract(t, runner)` — RunTask returns status, RepairTask includes failure context
- `validator.RunShellValidatorContract(t, v)` — passing checks → pass, failing → failure with diagnosis

Assertions are loose — structural compliance only (parseable output, required fields, valid enum values). No assertions on content quality.

**Completion criterion:** A domain adapter is not considered complete until its contract test suite passes against every configured LLM provider. If a provider cannot satisfy the structural contract, it is not a supported provider for that stage.

### Integration Scenarios (Prepared, Manual)

Scenario definitions ready to run manually against live providers:

1. **Happy path** — Compile → Plan → Execute → Validate (pass) → Review (no critical findings) → Accept (all pass). Assert: Status == Completed, cost > 0.
2. **Validation failure triggers repair** — Execute → Validate fails → diagnosis → RepairTask → Validate passes. Assert: task.Attempts == 2.
3. **Review triggers replan** — Review finds critical severity → ReplanFrom("plan"). Assert: cycle increments.
4. **Acceptance failure triggers replan** — Accept fails criterion → ReplanFrom("plan"). Assert: failed criteria in RunState.
5. **Budget exhaustion** — Cost exceeds budget between stages → loop stops. Assert: Status == Blocked.
6. **Provider fallback (0002d)** — Claude usage-limit → FallbackAdapter switches to Codex. Assert: two invocations, Claude marked unavailable.
7. **Router phase preferences (0002d)** — plan=claude, execute=any, review=claude. Assert: correct provider selected per phase.

## Decisions

1. **Provider-agnostic adapters over provider-specific adapters.** The Provider interface already abstracts CLI differences. Domain adapters should not know which LLM they talk to.

2. **Shared LLMAdapter base with per-domain thin adapters.** Common concerns (invoke, timeout, cost) live in the base. Domain-specific parsing lives in each adapter. Adding a provider requires zero adapter changes.

3. **No retry in LLMAdapter.** Retry strategies differ per domain (parse-error retry in planner, transient retry in acceptor, escalation in task runner). Callers own their retry logic.

4. **Shell-first validation, LLM on failure.** Running `go test` doesn't need an LLM. Understanding why tests failed does.

5. **Compile is deterministic.** Context packet assembly from files, no LLM invocation.

6. **0002c hardcodes Claude, 0002d adds Router.** Proves the adapter layer works with one provider before adding routing complexity.

7. **Contract tests run locally against real providers, not in CI.** Real LLM calls cost money and are nondeterministic. But they are a hard completion gate — adapters are not done until contracts pass against each real provider.

8. **FallbackAdapter is transparent.** Same `Invoke` signature as LLMAdapter — domain adapters don't know fallback exists underneath.
